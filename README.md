# DSA Visualizer

Paste a Python solution from NeetCode, give it a test input, and step through what
it actually did - line by line, with the data structures drawn and a tutor that can
answer questions about the run.

The design decision that matters: **the visualization is not generated by a model.**
Your code is executed under `sys.settrace` and every line, every variable, every call
and return is recorded. Claude sees that recording and writes the prose. It cannot
describe a loop that did not run, because it is reading a transcript rather than
imagining one.

## Setup

```bash
./run.sh
```

That creates a virtualenv, installs dependencies, copies `.env.example` to `.env`,
and starts the server at <http://127.0.0.1:8000>.

Add your key to `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Get one at <https://console.anthropic.com/settings/keys>. Without a key the tracer and
all the visualizations still work - you lose the written summary, the per-step
narration and the tutor chat.

By default the app asks the API which models your account can use and picks the newest
Sonnet. Pin a specific one with `ANTHROPIC_MODEL=...` in `.env` if you would rather.

## Using it

1. Paste the solution into the left pane. A `class Solution:` with a method, or a bare
   `def`, both work.
2. Put the test input underneath, in any of these shapes:
   - `nums = [2,7,11,15]` and `target = 9` on separate lines
   - `nums = [2,7,11,15], target = 9` on one line
   - `{"nums": [2,7,11,15], "target": 9}`
   - a bare `[2,7,11,15]` for a single-argument function
3. Hit **Run & Visualize** (or ⌘/Ctrl+Enter).

`head = [1,2,3]` is rebuilt into a real linked list, and `root = [3,9,20,None,None,15,7]`
into a real binary tree, using LeetCode's level-order encoding. You do not need to
include the `ListNode` / `TreeNode` class - it is injected if your solution does not
define one.

**Keyboard:** `←` `→` step, `space` play/pause, `⌘/Ctrl+Enter` run.

Thirteen worked Blind 75 problems are in the **Load an example** dropdown, one per
visualization type.

## What it draws

| Shape in your code | What you see |
|---|---|
| list, str | cells with indices, cursor flags, shaded window between two cursors |
| dict, set | key/value tiles, newly written keys flagged |
| list used as a stack | column with the top called out |
| `collections.deque` | row with front and back labelled |
| linked list nodes | nodes and arrows, with `prev` / `curr` / `slow` / `fast` labelling the node each sits on |
| binary tree nodes | laid-out tree; inside a recursion the whole tree is shown with the current node marked |
| list of equal-length lists | grid with the active cell lit and changed cells flagged |
| `heapq` list named `heap` / `pq` / … | the complete binary tree the array represents |
| dict of neighbour lists | graph with directed edges |
| any recursion | call tree with arguments and return values |

Any variable can be forced into a different compatible view with the **view as**
dropdown on its panel.

### Cursors

A variable is drawn as a cursor on a container when the source actually subscripts
that container with it - `nums[i]`, `dp[i][j]`, `s[right]`. Failing any such evidence,
a classic index name (`i`, `j`, `left`, `right`, `lo`, `hi`, `mid`, `slow`, `fast`, …)
still gets the benefit of the doubt, which covers `for i, n in enumerate(nums)`.
Names like `start`, `end` and `n` are deliberately *not* treated as cursors - they are
usually bounds or values, and a cursor pointing at the wrong thing is worse than none.

## Security

**This executes arbitrary Python that you paste in.** It runs in a subprocess with a
CPU limit, a memory limit and a wall-clock timeout, which is the right level of care
for a tool on your own laptop. It is not a sandbox.

Do not expose this server to a network, and do not paste code you have not read.
If you ever want to host it, the execution step needs a real sandbox first - a
container per run, or a service like gVisor or Firecracker.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `ANTHROPIC_API_KEY` | – | required for explanations and chat |
| `ANTHROPIC_MODEL` | newest Sonnet | pin a model |
| `DSA_MAX_STEPS` | `4000` | recorded steps before the trace is truncated |
| `DSA_TIMEOUT_SECONDS` | `10` | wall clock per run |

Raise `DSA_MAX_STEPS` for big inputs, but the point of this tool is small inputs you
can follow. A 4-element array teaches more than a 400-element one.

## Layout

```
backend/
  main.py          FastAPI routes
  runner.py        subprocess + rlimits + timeout
  trace_worker.py  the sys.settrace engine (runs in the child process)
  snapshot.py      live value -> JSON snapshot, with structure detection
  adapters.py      input parsing, entry-point discovery, ListNode/TreeNode building
  explain.py       Claude: summary, per-line narration templates, tutor chat
frontend/
  index.html
  css/app.css
  js/app.js        state, timeline, per-frame render
  js/api.js        fetch + SSE client
  js/chat.js       tutor panel
  js/renderers/    one module per visual form
  vendor/          CodeMirror, vendored so the app works offline
examples/          13 Blind 75 problems, one per visualization type
```

`AGENTS.md` has the internal contracts and the list of what is not built yet.
